# Code Audit — Electron Todo App

**Date:** 2026-05-15
**Scope:** `todo-app/` (main.js 430, preload.js 29, renderer/app.js 3292, renderer/index.html 353, renderer/styles.css 1937)
**Auditor:** Code review pass focused on security beyond Electron config, leaks, error handling, organization, accessibility, performance.
**Reviewer note:** Solo dev, internal-only, no public users. Recommendations are sized accordingly — no enterprise theatre.

---

## 1. Executive Summary

- **Security: B+.** Electron config is correct (contextIsolation, no nodeIntegration, IPC via preload allow-list). Renderer uses `escapeHtml()` on user fields inside every `innerHTML` interpolation **except `job.color`** (written verbatim into `style.background`) — see H-1. Main-process IPC payload validation is shallow (no array-length, field-type, or string-length checks on tasks).
- **Accessibility: D.** Only 4 ARIA-touching lines in the whole renderer. Modals are plain `<div class="modal hidden">` with no `role="dialog"`, no `aria-modal`, no focus trap, no return-focus to the previously focused element. Tab can leave the modal into the background board.
- **Performance: C+.** `renderAll()` is called from 13+ sites and rebuilds the entire board + table + calendar via `innerHTML = ''`, even when one task changed. No virtualization. For ~50 jobs × dozens of tasks this is fine on a desktop; at 200+ tasks the month calendar layout + ResizeObserver feedback is the first thing that will jank.
- **Quality: C.** 9 empty `catch (_) {}` blocks; one async IPC handler (`changeTaskStatus`, `saveData`) is fire-and-forget from click handlers (no error surfacing to user); `notifyAPI.show` is not awaited. ESLint/Prettier are absent (you noted this).
- **Maintainability: D+.** `app.js` is 3,292 lines in a single file. Five functions exceed 120 lines (`renderCalendarWeek` 169, `renderCalendarMonth` 162, `bindEvents` 146, `attachMonthBarDrag` 136, `attachWeekEventDrag` 121). Two named `onUp` drag closures with nearly identical lifecycle logic. The file mixes 12 conceptual modules (state, datepicker, timepicker, label picker, tour, notifications, calendar, board, list, modals, drag, persistence).

## 3. Top 5 Highest-ROI Actions (solo dev priority order)

1. **Fix the drag-handler leak (H-3, ~5 minutes).** Wrap both `onUp` bodies (line 1064, line 1370) in `try/finally` so `removeEventListener` always fires. Single highest-leverage memory-correctness fix in the file.
2. **Surface save failures to the user (H-2, ~20 minutes).** Add one helper `function fireAndForget(promise) { Promise.resolve(promise).catch(err => { console.error(err); showAlert('저장 실패: ' + err.message); }); }`. Use it at the 4-5 click handlers that call `changeTaskStatus`, `notifyAPI.show`, and `autoStartAPI.set`. Catches silent data loss on disk errors.
3. **Whitelist `job.color` on load (H-1, ~10 minutes).** In `loadData()` (around app.js:342) walk every job and replace `job.color` with `''` unless it matches `/^#[0-9a-fA-F]{6}$/`. Closes the only real injection vector you have.
4. **Replace empty catches with one-line warns (H-5, ~5 minutes).** 9 sites. Each `catch (_) {}` becomes `catch (err) { console.warn('xyz failed:', err); }`. Future debugging will thank you. The one at line 3289 needs to be narrowed to just the localStorage line, not the whole init block.
5. **Event-delegate the board status buttons (M-4, ~30 minutes).** One delegated listener at `els.board` replaces ~300 listener attaches per `renderAll`. Biggest perceived performance win; also closes the listener accumulation question entirely. Pair this with skipping the full `renderAll` from `changeTaskStatus` — just toggle classes on the changed card.

Cumulative: ~70 minutes of focused work for the entire top-5.

## 4. What's NOT a Problem (don't fix)

- **Electron security baseline.** `contextIsolation: true`, `nodeIntegration: false`, dedicated `preload.js` with a minimal `contextBridge` API surface, no `webSecurity:false`, no `enableRemoteModule`. Correct.
- **IPC channel allow-list.** `preload.js` exposes 5 small APIs with no passthrough function constructors and no `ipcRenderer` leak. Correct.
- **Single-instance lock.** `app.requestSingleInstanceLock()` + `second-instance` handler at main.js:14-25. Correct.
- **Window state persistence with `ensureBoundsVisible`.** main.js:92 checks bounds against current displays before restoring — handles monitor unplug. Correct.
- **Splash window + revealWindow safety net.** `MAX_SPLASH_DURATION = 8000` fallback at main.js:256 ensures the user is never stuck on a blank splash if `ready-to-show` never fires. Defensive but cheap. Correct.
- **`escapeHtml` usage on user-supplied task fields.** Title, memo, jobNo, dueDate are all escaped before innerHTML interpolation. Comprehensive at the 22 innerHTML sites. The one gap is `job.color` (H-1) and the class-name interpolations (which can't execute script).
- **`ensureDataFile` seeding.** main.js falls back to packaged `extraResources` on first launch, then to an empty `{jobs:[]}`. Robust.
- **Saved-state debouncing.** 250ms debounce on window move/resize at main.js:223 + flush on `close`. Correct trade-off.
- **JSON parse defensive.** Both `todo:load` and `settings:load` reject non-object / non-array shapes and return safe defaults. main.js:290, 322. Correct.
- **Notification scheduler de-dup.** `notifiedTaskIds` Set prevents repeat fires for the same task. Only flagged as M-7 because it's unbounded — not because de-dup is wrong.
- **Keyboard shortcuts respecting input focus.** app.js:3147-3151 checks `activeElement.tagName` and `anyModalOpen` before number-key view switching. Correct.
- **`requestAnimationFrame` for layout-dependent ops.** Used at 902, 2542 for measurement-after-layout. Correct.
- **`String.prototype.replace` for `cssEscape` of task IDs.** Currently bypassable but task IDs are internal `uid()` values — not user input. L-3 is a nit, not a real risk.
- **Hardware acceleration disabled.** You commented why (VM/RDP). Documented trade-off; leave it.
- **No CSP meta tag.** Electron app loading local `file://` content — CSP is low-value here given context isolation already blocks Node from the renderer. Skip.
- **No code signing / auto-update.** You explicitly noted internal-only. Skip.
